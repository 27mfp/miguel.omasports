Date: 2026-10-08
POC: Miguel (repository owner)

TL;DR: Happy-path tests pass. Fix notification cancellation, ESPN exceptional statuses, malformed-competitor handling, stale linescore propagation, and next-kickoff selection first. No exploitable security issue was confirmed in the reviewed paths.

## Scope and verification

Reviewed controller/request/retry/cancellation flows, provider parsing, derived-model identity, notifications, UI controls, filesystem/network/process boundaries, and CI/install guidance. No production code was changed.

- All 12 local quick-check suites passed: 94 model unit cases, seven ESPN sequence cases, offline provider fixtures, manifest/release contracts, security, scenarios, notifications, crests, burn-in, and Omarchy plugin validation.
- Live acceptance suite: 18 passed, zero failed, one skipped. The skipped football detail check had no live match available in the sampled leagues.
- Targeted Node probes reproduced incorrect ESPN exceptional statuses, a null-competitor parser exception, ignored linescore-only model changes, notification dispatch while disabled, and overdue next-kickoff selection.
- These probes load the production JavaScript or extract production Panel functions with mocked dependencies. They do not establish actual Qt signal ordering or visually verify the live desktop.
- No headless visual/interaction suite or full Quickshell runtime test was run. Those require a dedicated safe desktop setup. This is a broad code and behavioral audit, not an exhaustive security assessment or proof that no other bugs exist.

## Confirmed defects

### 1. High: queued notifications continue after disabling or switching sports

References: Panel.qml:1063-1118, 671-708, 1313-1337, 2487-2496, 2807-2812.

Enqueueing checks enableNotifications, but dispatchNextNotification does not. Disabling notifications does not discard the queue or stop the pacing timer. Sport-switch cancellation stops the notifier process but retains notificationQueue; notifier exit restarts the pacing timer. Old queued items can therefore dispatch after a preference change or sport switch.

Reproduction: enqueue a burst, disable notifications or change sports before the backlog drains. A probe calling the production dispatcher with enableNotifications=false still started notify-send.

Fix: centralize cancellation of queued alerts; clear the queue, stop pacing, and stop an active notifier when disabling or switching sports. Check enablement again at dispatch time. Add tests for the UI toggle, IPC setter, and sport switch.

### 2. High: postponed/canceled ESPN events become completed results

References: SportsModel.js:860-871, 899-905.

Generic state=post handling precedes cancellation-name handling, and postponement is not recognized. With state=post and STATUS_POSTPONED or STATUS_CANCELED, the parser emits status=finished and scoreText=0–0 for zero-score input. A postponed event can appear to be a completed draw.

Reproduction: both status names with post state reproduced finished/0–0 using the production parser.

Fix: classify exceptional status names before generic states, retain a suitable reason, and avoid fabricating final scores. Add canceled, postponed, delayed, and suspended cases with their intended UI semantics.

### 3. Medium: null competitor crashes the ESPN scoreboard parser

References: SportsModel.js:838-840, 878-885; Panel.qml:1764-1765.

The team-building loop skips null competitors, but the linescore loop dereferences competitors[cl] without a guard. A payload containing a null competitor throws instead of producing a partial result or a controlled provider error. The controller does not catch that normalization exception before completion coordination.

Reproduction: adding null to a valid event's competitors yielded Cannot read properties of null (reading 'homeAway'). This is a confirmed malformed-input bug; no live provider payload containing that null was observed.

Fix: validate each competitor in both loops and contain per-event failures so one bad event cannot disrupt the refresh round. Add malformed competitor and linescore-entry tests.

### 4. Medium: linescore-only updates retain old derived match objects

References: SportsModel.js:2675-2706, 2736-2745; Panel.qml:358-381, 625; LiveRow.qml:414-420; MatchSpotlight.qml:1122-1195.

sameMatches intentionally excludes period/inning linescores, and sameGroups uses that comparator. Panel retains its previous teamMatches/liveList/matchGroups arrays when other compared fields are unchanged. Those views can retain stale linescore data even though allMatches contains a fresh object. A favorite-team spotlight depends on the retained teamMatches list; the fallback spotlight directly using allMatches may update.

Reproduction: extending [1] to [1,0] with identical score/time/status returned true from both comparators. The retained-object behavior is established in code; its visible presentation has not been checked in Quickshell. Changes in liveTime or another compared field can incidentally refresh the data.

Fix: decouple delegate identity from data updates, or update existing match objects in place. Do not simply add linescores to the fingerprint without addressing the flicker/repeater churn the existing comment documents. Add a linescore-only update regression.

### 5. Medium: overdue upcoming fixture suppresses next-kickoff countdown

References: Panel.qml:387-400, 466-472.

refreshDerivedLists selects the earliest upcoming timestamp without excluding times at or before nowMs. nextKickoffText then hides that candidate rather than selecting the next future game. A stale provider status or delayed fixture can hide the countdown despite future games being present. As time advances, the cached candidate is also not reconsidered solely because its kickoff passed.

Reproduction: an upcoming event on Oct 7 and another on Oct 9 selected Oct 7, which the text binding would hide on Oct 8.

Fix: exclude overdue times and reconsider the candidate when its kickoff passes, without rescanning all matches every second. Test stale statuses and clock advancement with no new provider response.

## Improvements and coverage gaps

### 6. Medium: reduce ESPN polling cost and latency

References: Panel.qml:1704-1787, 1805-1817, 2723-2759.

Every refresh fetches five days sequentially plus standings. One missing day retries the whole window. Fast polling is conditionally 15 seconds, but sequential latency extends the effective refresh cadence. The loading guard prevents overlapping refreshes; no overlap bug was found.

Cache surrounding days and standings with separate TTLs; prioritize today's live slate and retry only failed days. Keep this separate from the compatibility fix already merged.

### 7. Medium: test actual retry timer and process-wrapper lifecycle

References: tests/espn-sequence.mjs:7-79, 125-143; NetworkProcess.qml:23-46, 72-94; Panel.qml:2648-2659.

The new deterministic tests execute real Panel functions, but simulate handled ordering and invoke the retry round manually. They do not execute the retry timer predicate/callback or NetworkProcess's completion timer and signals. The existing notification tests also simulate queue behavior instead of exercising cancellation paths.

Add timer-predicate tests and a small Quickshell integration test with controlled fake responses. Keep the current fast tests, but describe their scope accurately.

### 8. Medium: fixture subsection controls lack keyboard/accessibility support

References: FixturesTab.qml:522-591; Panel.qml:777-815.

All/Upcoming/Results/News are Rectangle/MouseArea delegates without accessible names/roles or keyboard activation. Custom focus navigation omits them.

Use focusable controls or add explicit role, name, selected state, keyboard activation, and entries in focus navigation.

### 9. Low: CI does not provide complete runtime QML validation

Reference: .github/workflows/tests.yml:54-90.

Hosted lint intentionally ignores unresolved Quickshell imports and fails only on syntax markers. This is useful syntax coverage, but it cannot prove all bindings, types, or interactions are correct.

Add an optional environment with Quickshell and a safe headless monitor for runtime/load/interaction coverage. Keep it separate from tests that could affect the user's desktop.

### 10. Low: consolidate install/update instructions

References: README.md:63-72; RUNNING.md:7-38; DEVELOPMENT.md.

README's copy/rescan/enable flow lacks RUNNING.md's linked-checkout and watcher-disabled restart caveats. Users can follow one document and still run previous QML. Some test counts in DEVELOPMENT.md are static snapshots.

Make README link to one authoritative update procedure and avoid hard-coded test counts where they will drift.

## Investigations, not established defects

- MLB/NHL playoff highlighting uses seed cutoffs (SportsModel.js:920-957). Confirm the provider's playoffSeed/group semantics against actual qualifiers before changing it; a hypothetical mismatch is not proof of a bug.
- ESPN day selection uses machine-local dates (SportsModel.js:639-655). Establish ESPN's date interpretation and test extreme timezones before calling this a missing-game bug. The existing five-day window already mitigates ordinary day offsets.
- Duplicate deferred ESPN starts could consume multiple dates if called twice (Panel.qml:1730-1738). Existing handled/generation guards appear to prevent that in normal operation. An idle/in-flight guard would be defensive hardening, not a reproduced fix.
- Invalid F1 calendar dates are retained as upcoming; stronger record validation would improve robustness, but no live malformed calendar event was observed.

## Security observations

No exploitable vulnerability was confirmed in the inspected paths. Positive controls include closed child environments and process-group cancellation; exact HTTPS host allowlists with redirect checks and size bounds; descriptor-relative, owned, no-follow state/cache operations; atomic writes; validated bounded PNG publication; validated external URLs; and argv-based notify-send calls with option termination. Security checks passed. Provider/CDN allowlist drift remains an availability maintenance concern.

## Suggested order

1. Notification cancellation and dispatch enablement checks.
2. Exceptional ESPN status normalization and malformed-event containment.
3. Linescore update propagation without delegate churn.
4. Future-only next-kickoff selection and clock rollover.
5. Regression coverage for timer/process runtime behavior and queued-notification cancellation.
6. ESPN cache/polling optimization.
7. Keyboard accessibility, runtime CI, and documentation consolidation.
